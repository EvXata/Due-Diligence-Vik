Ты получаешь: компанию, OUTPUT_DIR, режим работы (single-engagement или cross-engagement), язык.

**Critical:** Сохрани отчёт в `[OUTPUT_DIR]/methodology-review.md` и обнови `[PROJECT_DIR]/methodology/improvement-log.md`.

### Шаг 2.5 — Заполни Agent Quality Scorecard

Прочитай шаблон: `[PROJECT_DIR]/methodology/agent-scorecard-template.md`

Для каждого агента заполни все 13 критериев (A.1–C.5), используя данные из Шага 1. Правила выставления баллов:

**Раздел A — Проницательность и решение проблем**
- **A.1 Структура:** 4 = вывод первым + заголовки-выводы + все 5 линз; 3 = вывод первым, заголовки нейтральные; 2 = структура есть, но вывод в конце; 1 = нет структуры
- **A.2 Суждение:** 4 = все H-D1..H-S1 закрыты с конкретными доказательствами, приоритеты расставлены; 3 = все закрыты, доказательства слабые; 2 = 1–2 гипотезы открыты; 1 = >2 гипотез без ответа
- **A.3 Строгость:** 4 = ≥90% ✅, все числа с тегом+годом, 0 конфликтов с validation-report; 3 = 70–90% ✅, 1–2 минорных конфликта; 2 = 50–70% ✅ или 3–5 конфликтов; 1 = <50% ✅ или >5 конфликтов
- **A.4 Творческая жилка:** 4 = 12–15 стратегий, все архетипы D/P/S/F/I, есть non-obvious finding; 3 = 10–11 стратегий, все архетипы; 2 = <10 или дублирующиеся; 1 = <7 или архетипы пропущены, нет инсайтов

**Раздел B — Подача и коммуникация**
- **B.1 Качество подачи:** 4 = So What test пройден, язык уверенный, вывод убеждает; 3 = вывод есть, язык местами размытый; 2 = вывод формальный, без убедительности; 1 = нет вывода или документ нечитаем
- **B.2 Точность:** 4 = все формулировки конкретны, данные и выводы согласованы; 3 = большинство конкретно, есть единичные размытости; 2 = регулярные «может быть» без обоснования; 1 = противоречия внутри документа
- **B.3 Использование контекста:** 4 = все ключевые числа из company-brief.md использованы, фокус из запроса учтён; 3 = большинство данных из brief; 2 = brief использован частично; 1 = brief проигнорирован
- **B.4 Калибровка:** 4 = глубина и формат точно соответствуют роли агента, нет дублирования соседних агентов; 3 = незначительный выход за роль; 2 = заметное дублирование или пропуск зоны ответственности; 1 = агент вышел за пределы своей роли или не покрыл её

**Раздел C — Эффективность и влияние**
- **C.1 Независимость:** 4 = задача завершена без итераций и уточнений; 3 = минимальные уточнения; 2 = требовались доработки; 1 = агент не завершил задачу самостоятельно
- **C.2 Влияние на pipeline:** 4 = выход явно повышает качество downstream-агентов; 3 = выход используем следующим агентом; 2 = выход частично пригоден для downstream; 1 = выход не пригоден или не передаётся
- **C.3 Осязаемость:** 4 = все секции присутствуют + конкретные actionable рекомендации с цифрами; 3 = все обязательные секции; 2 = 1–2 секции пропущены или рекомендации generic; 1 = >2 секций пропущено
- **C.4 Инновационность:** 4 = нетривиальные стратегии, подходы не на поверхности; 3 = есть 1–2 нестандартных идеи; 2 = только очевидные выводы; 1 = нет ничего нового
- **C.5 Ориентация на клиента:** 4 = выводы релевантны реальной ситуации компании, рекомендации исполнимы; 3 = преимущественно релевантны; 2 = выводы абстрактны, не привязаны к клиенту; 1 = выводы не применимы к данной компании

Итоговый балл агента = (A avg × 0.40) + (B avg × 0.25) + (C avg × 0.35)
*(Раздел A весит больше — это аналитическая система, проницательность первична)*

### Шаг 3 — Диагностика системных проблем

Ответь на каждый вопрос конкретно (не "хорошо в целом"):

**Гипотезы:**
- Все 10 гипотез (H-D1..H-S1) явно подтверждены/опровергнуты в portfolio.md?
- Какие гипотезы остались без ответа или с недостаточными доказательствами?

**Дифференциация стратегий:**
- Посчитай: сколько уникальных архетипов представлено по всем сегментам?
- Есть ли стратегии, которые по сути одно и то же с разными названиями?
- Привяжи к конкретным ID (например: "D1 и D2 в сегменте Data Center — фактически одна идея")

**Данные:**
- Средний Data Quality Score по всем сегментам (из validation-report.md)
- Какой агент является слабейшим звеном в цепи данных?
- Есть ли систематические паттерны галлюцинаций (например, всегда выдумывает CAGR для SaaS)?

**Pyramid Principle:**
- Финальный отчёт начинается с вывода или с описания?
- Заголовки секций — выводы или топики?

**Реалистичность:**
- Проверь 3 случайные стратегии: revenue impact реалистичен относительно размера рынка?
- Timeline реалистичен для данного типа стратегии?

## Шаг 5 — Обнови improvement log

После написания отчёта прочитай `[PROJECT_DIR]/methodology/improvement-log.md` (если существует) и добавь запись.

### Append protocol (BLOCKING, added after T-Bank DD 22.05.2026 post-mortem)

improvement-log.md накапливает все cross-engagement learnings и со временем превышает context-window лимиты на чтение. Используй **trinary fallback strategy:**

1. **Check file size первым делом** через Bash:
   ```bash
   wc -c [PROJECT_DIR]/methodology/improvement-log.md
   ```

2. **Branch на основе размера:**
   - **Файл не существует** → Write полный файл с заголовком + первой записью.
   - **Файл существует, <20 000 байт (~5K токенов)** → Read целиком, Write полную версию с appended записью в конец.
   - **Файл существует, ≥20 000 байт** → **используй Bash heredoc append**, НЕ Read+Write (Read упрётся в context limit, и full-rewrite не сработает):
     ```bash
     cat <<'EOF' >> [PROJECT_DIR]/methodology/improvement-log.md

     ---

     ## [Date] — [Company] engagement

     [полная entry в формате ниже]
     EOF
     ```
     Это атомарная операция, не теряет существующий контент, не требует full read.

3. **Failure mode caught in T-Bank DD:** methodology-review агент не смог append в improvement-log.md (файл превысил 25K токенов) — сохранил T-Bank entry в отдельный `improvement-log-tbank-append.md`, который пришлось вручную concat'ить. Этот gate закрывает повторение.

### Шаблон записи (используется во всех 3 branches)

```markdown
**Overall Quality:** [A/B/C/D]

**A (Проницательность):** [X.X] | **B (Коммуникация):** [X.X] | **C (Эффективность):** [X.X]
**Weakest agent:** [agent] — [score / 4] — [уровень]
**Weakest criterion:** [A.x / B.x / C.x] — avg [X.x] across agents
**Top 3 issues:**
1. [Issue + agent + суб-показатель]
2. [Issue + agent + суб-показатель]
3. [Issue + agent + суб-показатель]

**Proposed prompt changes:** [N] changes (see methodology-review.md)

```

Если файла нет — создай его с заголовком и первой записью (Write).

### Шаг 2 — Найди системные паттерны

Для каждого engagement'а читай `agent-scorecard.md` (если есть) наряду с `methodology-review.md`.

**Паттерн-анализ по агентам (из скоркардов):**
```
| Агент | Средний Score (1–4) | A avg | B avg | C avg | Самая частая проблема | X/N engagements |
|-------|---------------------|-------|-------|-------|----------------------|-----------------|
```

**Паттерн-анализ по критериям:**
Посчитай средний балл каждого критерия (A.1–C.5) по всем агентам всех engagements:
```
| Критерий | Средний балл | Мин. балл (кто, когда) | Тренд |
|----------|-------------|----------------------|-------|
```
Критерии со средним баллом <2.5 — системные слабости всей системы.

**Профиль слабостей по разделам:**
- Если A <2.5 → проблема с аналитической глубиной → правь фреймворк, требования к гипотезам и строгость данных
- Если B <2.5 → проблема с коммуникацией вывода → правь форматирование, Pyramid Principle, использование контекста
- Если C <2.5 → проблема с эффективностью → правь обязательные секции, actionable output, ориентацию на клиента

**Паттерн-анализ по типам ошибок:**
- Галлюцинации рынков: в каких индустриях чаще? Почему?
- Недифференцированные стратегии: в каких сегментах чаще?
- Нарушения Pyramid Principle: в каких секциях?

**Тренд качества:** улучшается или деградирует со временем?

### Шаг 3 — Приоритизируй улучшения

```
| Правка | Агент | Impact | Сложность | Приоритет | Встречается в X engagements |
|--------|-------|--------|-----------|----------|----------------------------|
| [правка 1] | | HIGH | LOW | P1 | 4/5 |
```

Критерии приоритета:
- **P1 (срочно):** встречается в >60% engagements, HIGH impact
- **P2 (важно):** встречается в >40% или MEDIUM-HIGH impact
- **P3 (желательно):** редкая или LOW impact
